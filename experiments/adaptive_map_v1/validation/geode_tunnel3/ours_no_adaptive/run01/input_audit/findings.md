# Tunnel3 失稳段输入检查

只读检查 ROS2 bag，未修改算法或配置。可复现脚本：scripts/audit_tunnel3_input.py（需 source ROS2 和工作空间）。

时间原点为当前运行CSV首条 lidar_end_time=1706584908.6429248；检查相对125～145秒，不能直接当作播放器相对时间。

## 原始输入

- 200帧雷达，每帧24000条点记录；最大header间隔0.100652s。
- 外置 /imu/data 共2000条，最大header间隔0.014715s，没有非正间隔，角速度与加速度均有限。
- 加速度模长范围3.759～19.660m/s²，最大角速度模长0.864rad/s。这里存在动态运动；仅凭幅值不能断定IMU异常。
- 上述证明bag内没有长时间输入断档，不证明节点运行时没有队列丢失；现有CSV没有逐条接收IMU日志。

## 预处理留点

按当前Adaptive Livox路径离线重放line<6、tag、每3点抽1点、距离和相邻重复点规则。非有限点被离线显式排除。下表是每帧计数的中位数，不是有效匹配点数。

| 指标 | 125～130s | 131～136s | 140～145s |
|---|---:|---:|---:|
| 原始记录数 | 24000 | 24000 | 24000 |
| 非零距离记录数 | 20915 | 21499 | 21726.5 |
| line/tag后 | 23999 | 23999 | 23999 |

| 离线blind=1m保留 | 6842 | 7076 | 7140.5 |
| 当前4m、0.5m体素数量估算 | 845 | 33 | 1456.5 |

体素数量只是在未去畸变原始坐标中计算的占据体素数，不等同于运行时PCL输出。131～136s当前4m保留点最少0个；距离>4m的重复点剔除数量全部为0。主因不是line/tag或相邻重复点规则，而是4m近距离排除与当时场景可见距离的组合。

FAST-LIO2与Adaptive当前GEODE配置均为blind=4m、point_filter_num=3。因此它能解释两者在同一时段约束变少的共同风险，不能单独解释两者ATE差距。较小盲区的离线留点数量也不保证这些点都可靠或能提供缺失方向约束。

## 建议

优先做blind=2m的单变量敏感性实验，保持体素0.5m、初始化、噪声、播放速度等不变。先测关闭Adaptive的Tunnel3；若改善，再用相同盲区测FAST-LIO2，单列结果，不能混入原blind=4m矩阵直接归因于模块。

当前仍不宜直接新增“零有效点禁止入图”策略，也不应同时改队列或初始化。若2m无改善，再逐步核查两套IMU初始化、积分边界和运行时接收差异。
