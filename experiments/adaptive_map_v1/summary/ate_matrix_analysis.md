# 当前ATE矩阵分析

主文件：ate_experiment_matrix.csv。14条序列，三种方法，单位m；Tunnel1～5均采用2米盲区。用户已确认ours_adaptive隧道五组为2米，FAST-LIO2和关闭组使用对应blind2目录。共核验52份原始CSV的哈希与评分manifest。

## 实验有效性

Offroad1～3已补跑，当前ours_adaptive记录中adaptive_map全部为1，质量拒绝计数分别为100114、85130、79839。官方流程ATE分别为0.086774、0.107786、0.093716m，已填入矩阵。之前开关为0的评分产物已归档到各run01下的evaluation_previous_*目录；ate_run_details.csv现在对应新记录。

空值不是零误差，也不是算法失败X，而是缺少符合该角色的记录。status=scored只代表评分成功，不代表轨迹覆盖完整或算法稳定。

## 当前结果支持什么

14条有效开启组中，相对关闭模块6条ATE下降、8条上升；相对FAST-LIO2则8条下降、6条上升。每条均为当前保留的一次运行，不作为统计显著性结论。

- Offroad1～3：关闭0.077155、0.102416、0.087325m，开启0.086774、0.107786、0.093716m，三组分别增加0.009619、0.005370、0.006391m。当前没有显示模块增益，但均为毫米至厘米量级差异，需要重复试验确定是否超过运行波动。相对FAST-LIO2仅Offroad1更低。

- Tunnel2：关闭5.640907 → 开启2.169827m；FAST-LIO2为18.292805m。仍有明显误差，尚不能只凭一次运行称为稳定解决退化。
- Tunnel3：关闭0.146799 → 开启4.756198m；FAST-LIO2为0.278646m。这是优先诊断的退步序列。此前4米关闭组9.624905m不能用于证明当前2米开启组提升。
- Tunnel5：关闭1.852172 → 开启0.866253m；FAST-LIO2为1.396598m。
- Tunnel1、4差值较小，需要重复试验判断是否超过运行波动。
- Waterway Short/Medium：开启后分别从0.248172升至0.367010m、0.739867升至0.840257m，两组均未显示增益。
- NTU SPMS1/3：关闭5.610317、1.423322m，开启0.267194、0.452999m；改善明显，但记录行数、关联样本及起止覆盖不同，需在共同时间支持上复核。
- NTU SPMS2：关闭4.142781 → 开启4.828395m，未见改善。
- SubT：关闭1.530303 → 开启1.459600m，改变量较小，不能拿与FAST-LIO2的6.546465m差距全部归因于Adaptive Map，因为关闭组已与FAST-LIO2有明显差距。

## 模式与作用

14条有效开启记录均存在质量筛选计数。仅SubT出现Persistent（135/2526帧，约5.34%）；其余有效开启组模式为Normal或Transient。Offroad1～3的Transient分别为26/4028、443/4194、44/3202帧。因此这些实验主要检验基础质量筛选及Transient入图行为，不能据此单独证明Persistent配额有效或无效。没有通过模式计数确定失败原因。

## 建议顺序

1. Offroad三组已补齐，保存当前14条序列的完整矩阵和评分依据。
2. 固定当前代码和参数，优先检查Tunnel3开启组在稀疏点时段的匹配与入图差异，再做开关成对重复实验。两组均保留2米盲区及相同少于5点保护。
3. 对明显改善的SPMS1/3与Tunnel2/5核对共同时间覆盖，保存重复运行，不择优覆盖。
4. 按场景报告增益与退步，不把不同数据集协议的ATE直接平均成唯一总指标。基础实现差异与初始化差异仍需写入实验限制。

GEODE均执行本地官方转换及rmse.py，延续帧尾时间和offset=+0.1s（作用于第二输入GT）的约定；NTU为现有Python协议实现，未运行官方MATLAB；SubT采用evo SE(3)、max_diff=0.1s、offset=0。所有结果按各自关联样本计算。
